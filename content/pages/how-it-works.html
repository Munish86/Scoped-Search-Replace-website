How it works

One real change, from start to finish

A small coffee shop moved its site from http://harbour-coffee.example to https://www.harbour-coffee.example. Its published pages still link to the old address. Here is how they fixed it, with screenshots taken from the plugin itself.

Step 1

Take a backup, then open the tool

After activating the plugin, Search & Replace appears in the left-hand admin menu (and as "Open tool" on the Plugins screen). The page has two cards: Search and Count, and Find and Replace.

The yellow notice at the top is the plugin's own reminder: back up the site before replacing anything, and search first.

Step 2

Choose the scope

The links are in the text of the pages, so the shop picked:

  • Table: wp_posts, field: Post/Page Content
  • Content type: Page
  • Status: Published, so the draft Christmas gift guide stays as it is for now
  • Specific page: all matching pages (pick one from the list to limit it further)

Step 3

Search and count

They searched for http://harbour-coffee.example. Result: 5 matching rows, 12 occurrences, on five pages. Each row has Edit and View links, so they opened Brew guides (4 matches) to check what would change.

Nothing has been changed yet. Searching is always safe.

Step 4

Replace in the same scope

In Find and Replace they set the same scope, entered the old and the new address, and clicked Replace Selected Records. Before anything is saved, the browser asks:

Please review the replacement:

Old value:
http://harbour-coffee.example

New value:
https://www.harbour-coffee.example

Table: wp_posts
Field: Post/Page Content
Scope: All pages/posts matching the selected filters

Create a backup before continuing. Do you want to proceed?

Step 5

Check the result

"Replacement completed. Updated 5 database row(s) and replaced 12 occurrence(s)." The plugin then searched the scope again: nothing left.

Next, they ran the same steps with the post meta table, where two button links and a serialized layout setting still held the old address.

Tips

Getting the scope right

No matches?

The tool starts on Post and Published. For pages, products or drafts, change the content type or status. Also check capitals: the search is case-sensitive.

Content, then custom fields

A URL often lives in both places. Run the content of the posts table first, then post meta, and search both again at the end.

Try it small

Not sure about a change? Run it on one page first, check that page in the browser, then widen the scope to all pages.
