The problem

Changing one link shouldn't put the whole database at risk

A new domain, a move to https, a phone number that changed, a typo in a link used on forty pages. The fix is simple. Doing it safely in the database is not.

All or nothing

Most replace tools work on whole tables. You wanted to fix the blog posts, and the change also reached drafts, revisions and settings you never meant to touch.

Broken builder layouts

Page builders and plugins store data in a serialized format that records the length of every text. A plain SQL replace changes the text but not the length, and the data stops loading.

No idea what will change

Clicking "Replace" without knowing how many rows match, or which pages they are, is a guess. On a live site, a guess is expensive.

Scope

Say exactly where the change may happen

Five choices decide the scope, and the same choices are used for the search and for the replacement. Want to fix only the Wholesale page? Pick it from the list, and every other page stays as it is.

  • Posts table: content, title or excerpt. Post meta: custom field values
  • Any public content type: posts, pages, products, portfolios and more
  • Published, draft, pending review, private, scheduled, or all
  • The page list only shows items that match the type and status you chose

Search and count

Know the numbers before you change anything

A search never changes your data. It tells you how many database rows match and how many times the text appears in total, then lists every record so you can open it and check.

  • Exact, case-sensitive matching: the count is what will be replaced
  • Title, type, status and number of matches for each record
  • For custom fields, the meta key is shown too

Custom fields

Page builder data, replaced without breaking it

Builders, themes and plugins often keep settings as serialized arrays in post meta. The plugin unpacks each value, replaces the text inside, and packs it again with the correct lengths. A row whose data is already damaged is skipped and reported by its ID, never overwritten.

Questions

Is it really free?

Yes. The plugin is free and open source under the GPLv2 or later licence. There is no paid version, no account to create and no limit on how often you use it.

Can I undo a replacement?

Not with one click: changes are written straight to the database. Take a backup first and run a search to review the matching records. If needed, you can replace the new value back with the old one inside the same scope.

Does it work with Elementor and other page builders?

Yes, when the builder keeps its data in post meta: choose the post meta table. Serialized values are handled safely. Some builders also keep generated CSS files; regenerate them from the builder's settings after a replacement. More in the docs

Does it change my site settings, users or comments?

No. The options table, users, comments, terms and custom tables are never searched or changed. The plugin works on posts, pages, other content types and their custom fields only.

Does it work on multisite?

Yes. It works on the site you are viewing; each site in the network is searched and changed separately.
